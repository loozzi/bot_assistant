# Postgres ORM + Alembic Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the project a real SQLAlchemy `Base`/`User` model in `app/models.py` and a working Alembic migration setup, wired to the same `Settings` object the app already uses — closing the "no Postgres models/migrations" gap without touching the already-working async connection pool.

**Architecture:** `app/models.py` defines a `DeclarativeBase` subclass (`Base`) and a minimal `User` model. Alembic runs migrations through a **separate sync driver** (`psycopg2`) so the app's async runtime pool (`app/infra/db/session.py`, unchanged) and the migration tool never share a driver. `alembic/env.py` builds its engine from a new `Settings.postgres_sync_dsn` property — never a hand-maintained duplicate URL — and points `target_metadata` at `Base.metadata`.

**Tech Stack:** SQLAlchemy 2.x (`DeclarativeBase`, `Mapped`, `mapped_column`), Alembic, psycopg2-binary (migrations only), asyncpg (app runtime, already present), uv for dependency management.

## Global Constraints

- App runtime DB driver stays asyncpg (`postgresql+asyncpg://`) via `Settings.postgres_dsn` — do not change `app/infra/db/session.py`.
- Migrations use a dedicated sync driver (`postgresql+psycopg2://`) via new `Settings.postgres_sync_dsn` — never hardcode a DSN inside `alembic.ini` or `alembic/env.py`.
- `app/models.py` holds only `Base` + `User` in this plan. No per-module tables (journal/finance/todo/insight) — out of scope per the spec.
- No test suite/pytest is configured in this repo (per `CLAUDE.md`) — verification steps in this plan use `uv run alembic ...` and manual `psql`/Python checks, not pytest.
- Local Postgres for verification comes from `docker compose up -d postgres`, credentials from the existing `.env` file at the repo root.

- [ ] **Step 1: Write the model**

```python
from datetime import datetime

from sqlalchemy import BigInteger, func
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column


class Base(DeclarativeBase):
    pass


class User(Base):
    __tablename__ = "users"

    id: Mapped[int] = mapped_column(primary_key=True)
    telegram_id: Mapped[int] = mapped_column(BigInteger, unique=True, index=True)
    created_at: Mapped[datetime] = mapped_column(server_default=func.now())
```

`BigInteger` is required because Telegram user IDs can exceed the 32-bit `Integer` range.

```python
from logging.config import fileConfig

from alembic import context
from sqlalchemy import engine_from_config, pool

from app.config.settings import get_settings
from app.models import Base

config = context.config

if config.config_file_name is not None:
    fileConfig(config.config_file_name)

target_metadata = Base.metadata


def get_url() -> str:
    return get_settings().postgres_sync_dsn


def run_migrations_offline() -> None:
    context.configure(
        url=get_url(),
        target_metadata=target_metadata,
        literal_binds=True,
        dialect_opts={"paramstyle": "named"},
    )

    with context.begin_transaction():
        context.run_migrations()


def run_migrations_online() -> None:
    configuration = config.get_section(config.config_ini_section, {})
    configuration["sqlalchemy.url"] = get_url()

    connectable = engine_from_config(
        configuration,
        prefix="sqlalchemy.",
        poolclass=pool.NullPool,
    )

    with connectable.connect() as connection:
        context.configure(connection=connection, target_metadata=target_metadata)

        with context.begin_transaction():
            context.run_migrations()


if context.is_offline_mode():
    run_migrations_offline()
else:
    run_migrations_online()
```
